# admin-database rules



- **Long-Running Operation Polling Lifecycle & Unmount Cleanup**: When triggering backend jobs (such as database backup or restore operations) that may take longer than standard request timeouts (e.g. Heroku's 30s limit), client-side polling must never be terminated by an arbitrary client-side attempt count (e.g. 30 attempts). Polling must continue until a server-authoritative terminal state (`completed` or `failed`) or fatal error is returned. Furthermore, own the polling lifecycle in a dedicated React effect or ref structure: cancel pending timer handles and flag cancellations upon component unmount, sign-out, or authorization/token changes so that in-flight network responses are safely discarded without updating unmounted or unauthorized sessions.


- **Backup & Operational Runs Table Size Column**: Per the MongoDB backup/restore design specification (`backup-restore/mongodb-backup-restore-design-2026-10-07.md`), backup run summary tables must include a dedicated `Size` column formatted with human-readable units (e.g. `B`, `KB`, `MB`, `GB` or an em-dash `—` for null/unrecorded sizes) alongside `When it ran`, `Trigger`, `State`, `Counts`, and `Dropbox path`, and collapsible detail/empty rows must account for the full column span (`colSpan={7}`).


- **Dialog Form State Reset on Open Transition Only**: In child dialog components receiving collection props that update during polling or parent refreshes (e.g. `runs: BackupRunSummary[]`), resetting form state in an effect that depends on the collection prop wipes out user-typed inputs (e.g. typed confirmation strings), in-flight operations, or completed operation results whenever the parent component re-fetches. Use a previous-open ref (`const prevOpenRef = React.useRef(false);`) and trigger form resets strictly on the closed-to-open transition (`open && !prevOpenRef.current`), leaving existing inputs and operation progress intact during background refreshes while the dialog is open.


- **Dynamic Imports and Vite Modulepreload Bundle Leaks**: When dynamically importing a heavy library (such as Mermaid via `await import('mermaid')`) inside a child component, importing that child component statically into a page entry file causes Vite's build-time modulepreload scanner to place chunk preload links into the parent entry chunk (`dist/assets/index-*.js`). This results in occurrences of the library's chunk name or symbols inside the entry bundle, violating bundle isolation rules. To ensure 0 occurrences of the library inside the entry bundle, mount the child component via `React.lazy(() => import('./ChildComponent'))` wrapped in `<React.Suspense>`.


- **Never Manufacture Safety or Verification Results from Fallbacks**: When consuming asynchronous or polling operations that perform critical data transformations or safety sanitizations (such as copying production data to DEV with PII scrubbing, email replacement, and read-back verification), NEVER synthesize or manufacture default "clean" or "successful" results (e.g. `clean: true`, `readBack: { status: 'none', message: 'clean' }`) when the server response lacks an actual operation result (`result: null` or omitted). An operation terminal state (`status: 'completed'`) alone does NOT prove that safety verification succeeded. UI components must require authoritative, validated result structures before displaying success banners or clean verification statements, and must surface an error or unverified alert if the result payload is missing, null, or malformed.


- **Deep Structural Validation for Unknown API Results and Verification Consistency**: Type guard functions validating `unknown` API result payloads (such as `isValidRestoreResult` and `isValidCopyResult`) must deeply validate every record and nested collection consumed by the UI (e.g. ensuring row objects are non-null and contain required numeric/string fields, and index lists are valid arrays of objects) before returning true, rather than shallowly checking `Array.isArray(collections)`. Accepting shallow or incomplete records allows unvalidated items to crash UI render loops (e.g. calling `.toLocaleString()` on undefined/null counts). Furthermore, guards must validate the internal consistency of compound safety assertions: when an operation reports `clean: true`, it must require authoritative positive verification (`status === 'none'` and zero remaining violations), rejecting contradictory states (e.g. `clean: true` with a failed read-back or missing counts), and UI display components must never supply fallback defaults that convert empty or missing verification strings into "clean".
