# inquiry rules



- **Inquiry Form Metadata, Spam Protection & Booking Fields**:
  - **Single Source of Truth in `formData`**: When collecting form metadata (such as `form`, `website`, `formLoadedAt`), initialize all fields once in component state (`formData`) and require callers to explicitly supply the form identifier (`<Inquiry form="webjam-homepage" />` or `<Inquiry form="jam-bookus" />`). Avoid redundant prop-threading through intermediate form components, and do not re-merge or overwrite state in submission click handlers.
  - **No Submission-Time Load-Time Fallbacks**: Never supply submission-time fallback defaults for interaction timestamps (e.g. defaulting `formLoadedAt` to `Date.now()`). Defaulting to the current time at submit time yields `now - formLoadedAt ~ 0ms`, falsely tripping the backend's minimum human interaction speed check (< 3 seconds) and rejecting valid submissions as bot spam.
  - **Booking Fields Validation & Google Places Autocomplete**: Client-side validation requires `eventDate`, `eventType`, and either `venuePlaceId` or `venueAddress` for Book Us (`jam-bookus` / `showBookingFields`), while the Homepage inquiry form remains unconstrained. If `GOOGLE_MAPS_API_KEY` is missing or Google Maps script fails to load, `VenueAddressInput` gracefully degrades to a manual text input with an informative note and submits `venueAddress`. When a suggestion is picked, `venuePlaceId` is submitted and `venueAddress` is omitted.
  - **Testing Autocomplete with Listbox Roles**: In Vitest / testing-library tests, native `<select>` options also have `role="option"`. When asserting suggestion items in custom dropdowns, scope queries to the suggestions listbox (`within(screen.getByRole('listbox')).getAllByRole('option')`) to avoid collisions with country/state `<select>` options.
  - **Preserve Intervening Form State & Bound Async Third-Party Lookups**: When an autocomplete or suggestions component performs async secondary requests (such as fetching place details via Google Places), never spread stale form state captured at click time when the promise resolves. Read the latest form state from a ref (or updater function) so intervening customer edits to other fields are preserved, and discard the async completion if the user has since changed the input or selection. Furthermore, every third-party loader and lookup request (script loading, library imports, predictions, and details) must be guarded with bounded timeouts, so that if the external service hangs or fails to answer (neither resolving nor rejecting), the component gracefully degrades to manual input with the latest typed text rather than leaving submission disabled indefinitely. Late responses arriving after fallback must be ignored.
  - **Relative Future Dates in E2E Browser Form Validation**: In Playwright E2E tests validating date pickers with "today or later" constraints, never hardcode static calendar dates without freezing the browser clock. Use relative future dates computed from `Date.now()` (e.g. `new Date(Date.now() + 30 * 86400000).toISOString().slice(0, 10)`) and assert the dynamically computed date in intercepted submission payloads so tests do not expire and fail after static calendar dates pass.
  - **Clean E2E Test Listeners**: Never leave temporary debug listeners (`page.on('console', ...)`, `page.on('pageerror', ...)`) active in checked-in Playwright E2E test suites.
