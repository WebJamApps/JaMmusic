# tests rules



- **E2E Selector Migration for Responsive Layout Breakpoints**: When a desktop data table
  (e.g. `.MuiDataGrid-root` / `.MuiDataGrid-row`) is responsively transformed into a card layout
  (e.g. `.gig-card`) below a specific viewport breakpoint, shared E2E test helpers (such as `openGigDialog`)
  and browser test suites must not unconditionally query removed desktop table selectors. Because Playwright
  mobile projects (such as `Pixel 5`) run at narrow viewports (< 960px), helpers and assertions must detect
  whether card elements or table elements are visible, exercising cards at narrow viewports while retaining
  desktop table coverage when viewports are resized.


- **Playwright E2E Mocking for External Auth & Background Transports**: When writing or extending Playwright browser test
  suites for pages embedded in the root App (such as Admin pages under `AppTemplate`), external identity providers (such as
  Google Identity Services at `https://accounts.google.com/gsi/client`) injected by providers like `GoogleOAuthProvider`
  must be explicitly aborted (`await page.route(/accounts\.google\.com/, route => route.abort())`) to prevent unhandled
  runtime script exceptions from breaking React root mounting in headless Chrome. Background poll/socket endpoints (e.g.
  SocketCluster WebSocket connections and initial collection requests like `**/song*`) must also be mocked so unhandled
  background network failures do not delay element stabilization or trigger error overlays.


- **Vite Production Builds**: Local environment variables (e.g., `NODE_ENV=development` in `.env`) can bleed into `npm run build` and compile a development-mode bundle containing React development helpers. This causes a critical browser runtime crash with the error: `TypeError: (0, X.jsxDEV) is not a function`. To compile a pure, clean production bundle, always prefix the build command: `NODE_ENV=production npm run build`.


- **Playwright selectors for Material-UI Typography**: Material-UI's `<Typography>` component compiles to `<p>` tags (or other tags like `<h1>` or `<h6>` based on variants) by default, **never** `<span>` tags. Avoid utilizing tag-locked selectors like `span:has-text("...")` in E2E/Playwright tests, as they will timeout. Instead, use tag-agnostic text selectors like `:text("...")` or `p:has-text("...")`.


- **Running Playwright E2E Tests Locally**: `playwright.config.ts` defaults to `http://localhost:7878` and starts its own server (`npm run build && npm run preview -- --port 7878`), so `npm run test:e2e` tests your local code with no server started first. Run `npm run test:e2e:install` once to install the browser. Locally it reuses a server already listening on port 7878, so stop any old preview first. To run one spec, pass part of its file name: `npm run test:e2e -- <name>`. Set `BASE_URL` only to point the suite at a different server.


- **Vitest Unit Tests and Environment Variables**: Local unit tests inspecting `checkIsAdmin` that parse `process.env.userRoles` must supply a fallback `userRoles` JSON string (e.g., `process.env.userRoles || JSON.stringify({ roles: ['admin'] })`) to be self-contained and pass on clean checkouts where `.env` is absent.


- **Worktree node_modules Symlink**: In temporary git worktrees, `node_modules` is not symlinked by default. Symlink the main repo's `node_modules` (`ln -s /home/joshua/WebJamApps/JaMmusic/node_modules node_modules`) so test tools (`tsc`, `stylelint`, `vitest`) are available. Unlink or exclude the symlink before committing.


- **Testing Library Jest-DOM Import**: In Vitest unit tests using DOM element matchers such as `toHaveAttribute`, `toBeInTheDocument`, or `toHaveTextContent`, always include `import '@testing-library/jest-dom';` at the top of the spec file to extend Vitest's `expect` matchers.


- **Date Formatting & Timezone Mismatch in Vitest Snapshots**: React date inputs and localized date string components render local time strings (e.g. `GMT-0500 Eastern Standard Time`) when snapshots are updated locally. On CircleCI Linux runners operating in `UTC` (`GMT+0000`), timezone mismatches break unit test assertions. Always run snapshot updates with `npm run test:unit-u` (or `TZ=UTC npx vitest run -u`) so snapshot outputs align with CI.


- **BackendUrl and Production Builds**: In production builds, `BackendUrl` defaults to an empty string indicating same-origin requests (`${BackendUrl}/song` resolves to `/song`). `vite.config.ts` carries a build-time guard that refuses production builds whenever `BackendUrl` resolves to `localhost` unless `ALLOW_LOCALHOST_BACKEND=true` is explicitly set (e.g., for local Playwright E2E suites). Running E2E tests with `ALLOW_LOCALHOST_BACKEND=true` compiles a local test bundle into `dist/` containing `localhost:7000`. Running `npm test` (specifically `test/build_backend_url.test.ts`) while that `dist/` directory exists will fail the assertion verifying that production dist assets contain 0 occurrences of `localhost:7000`; remove `dist/` (`rm -rf dist`) before running `npm test`.


- **E2E & Playwright CI Verification**: When an issue specifies continuous verification or execution in CI for Playwright/E2E tests, ensure `.circleci/config.yml` installs browser dependencies (`npx playwright install --with-deps chromium`) and executes `npm run test:e2e`, and ensure `playwright.config.ts` defines a `webServer` with `command: 'npm run build && npm run preview -- --port <port>'` (e.g. `npm run build && npm run preview -- --port 7878`) with a local default `baseURL` so production JSX runtime is generated without `jsxDEV` mismatch errors and E2E tests run self-contained in CI without manual external server startup. Furthermore, `playwright.config.ts`'s `webServer.env` must never rely on a bare fallback `process.env.userRoles || JSON.stringify({ roles: ['Developer', 'JaM-admin'] })`: ambient CI project settings can set an incomplete `userRoles` (e.g. containing only `Developer` or `admin`), which overrides the fallback and causes role-gated UI elements (`checkIsAllowed` filtering by `userRoles.indexOf(auth.user.userType)`) to vanish (`Error: element(s) not found` on `getByRole('button', { name: 'Admin' })`). `playwright.config.ts` must parse and union-merge required E2E roles (`Developer`, `JaM-admin`) into `webServer.env.userRoles`, and `.circleci/config.yml` must explicitly configure `userRoles: '{"roles":["Developer","JaM-admin"]}'` under the E2E test step's `environment` block. In addition, when rebasing a feature branch onto `dev`, ensure the semver version bump in `package.json` is preserved/updated relative to the new `dev` base.


- **React Router Link vs Anchor in SideMenuItem & E2E Client Navigation Testing**: In `src/App/AppTemplate/SideMenuItem.tsx` (`ContinueMenuItem`), menu items with links containing `/music` only render as react-router `<Link>` components when the current route is on a music path (`isMusicPath && link.includes('/music')`). When on other paths (such as `/`), they render standard `<a>` tags. Therefore, E2E tests verifying client-side `<Link>` transitions must initiate from a music route (e.g. `/music`) to genuinely exercise React Router's `Link` component. In addition:
  1. Never wrap link clicks and assertions in `if (await link.isVisible())` guards, which silently pass if the link fails to render; use `await expect(link).toBeVisible()` so missing controls fail the test immediately.
  2. Prove no full page reload occurred by setting a window canary (`await page.evaluate(() => { window.__noReload = true; })`) before clicking and asserting `expect(noReload).toBe(true)` afterwards (full page loads reset window properties).
  3. When testing browser back/forward stack traversal, avoid building history with consecutive `page.goto()` calls (which trigger full browser page loads); construct history entries by clicking `<Link>` elements, then verify `page.goBack()` and `page.goForward()` navigate React Router's internal history stack.
  4. When testing `useSearchParams`, do not merely assert that the URL retains query parameters; assert that the component logic consuming the query parameter (such as `utils.initSongs` reading `?id=...` to enter single-song view) executes and renders the expected distinct UI state.


- **Strict Mock Typing and Avoiding Raw `as any` Across Unit and E2E Tests**: JaMmusic bans raw `any` / `as any` in both unit test mocks and E2E specs (`test/e2e/`). In unit tests, always apply strict casts using `as unknown as typeof <target>` or `vi.spyOn(target, 'method').mockResolvedValue(...)` so mock assignments satisfy TypeScript without dropping compile-time type safety. In Playwright E2E helper functions, type parameters explicitly with imported types from `@playwright/test` (such as `page: Page`, `route: Route`, `ws: WebSocketRoute`).


- **Sticky Table Headers & jsdom Styling Limitations vs Playwright E2E**: In jsdom unit tests with mocked `@mui/material` components (e.g. `TableCell` returning `<td {...props}>`), Material-UI `sx` properties (such as `position: sticky` and `backgroundColor: 'background.paper'`) pass through as raw object properties rather than being compiled by Emotion into computed CSS. Consequently, `expect(element).toHaveStyle(...)` will fail in jsdom for `sx`-driven styles. Unit tests should assert presence and semantic attributes, while visual and layout behaviors like sticky column pinning and opaque scroll backgrounds should be covered through browser E2E specs in `test/e2e/`.


- **Playwright Route Matching Across Path Separators (`**` vs `*`) and HTML Document Navigation Guards**: In Playwright's `page.route()`, single asterisks in URL globs (e.g. `'http://localhost:7000/venue*'`) do not match across path separators (`/`). Sub-routes and nested endpoints like `http://localhost:7000/venue/v1` will bypass the mock, fall back to the real network, and fail with `ERR_CONNECTION_REFUSED`. Use double asterisks (`'**/venue**'`) or a RegExp pattern (e.g. `/venue(\/|\?|$)/`) to intercept both collection and item/subresource endpoints. In addition, when matching API endpoints with broad patterns (e.g. `**/venue*`, `**/admin/user*`), guard against intercepting full-page HTML document navigations (such as `/admin/venues` matching `**/venue*`): always check `if (route.request().resourceType() === 'document') { await route.continue(); return; }` so Playwright serves the HTML bundle rather than returning mock JSON and crashing the page render.


- **Table Pagination, Default Sorting, and Inline Row Updates in E2E**: In tables with pagination and primary sort fields (such as sorting by `prospect` where eligible venues precede ineligible ones), inline editing of a sort field (e.g. toggling `outreachEligible` to `false`) moves the edited item behind other items upon refresh. If the dataset exceeds the page size (e.g. 10 items), the updated row can be pushed to page 2 and disappear from the DOM. Configure mock rows (such as setting other mock rows' `outreachEligible: false`) so the edited row remains stable on page 1 for post-update assertions.


- **Third-Party Script Races in E2E Suites**: External scripts loaded asynchronously (such as Google Maps API) can resolve mid-test and trigger conditional component replacement (e.g. replacing a `<TextField>` with an `<Autocomplete>`), wiping out form inputs typed before the script finished loading. In E2E suites where external services are not explicitly tested, abort external requests in `beforeEach` (e.g. `page.route(/maps\.googleapis\.com/, route => route.abort())`) to guarantee deterministic rendering and avoid race conditions.


- **WebSocket Mock Handshake in E2E Suites & Real Pointer Activation**: In E2E suites where WebSocket / SocketCluster connections are initialized, closing the socket abruptly (`ws.close()`) or leaving it unmocked triggers global network failure notifications (`commonUtils.notify(...)` via `Toastify`). The resulting fixed toast overlays (`.Toastify__toast-container--top-right`) intercept pointer events and cause locator clicks on header and sidebar toggles (such as `#mobilemenutoggle`) to time out. Always handle SocketCluster packets via `page.routeWebSocket` by intercepting `#handshake`, `#subscribe`, and `initial message`, responding with valid payloads (`{ id: 'fixture', pingTimeout: 20000 }`, empty collection arrays) to keep the app clean of error toasts. Furthermore, exercise real user interactions with `locator.click()` or `locator.tap()` instead of synthetic DOM events (`dispatchEvent('click')` or DOM `.click()`), ensuring Playwright verifies visibility, stability, and hit-testing without masking pointer-interception regressions.


- **Vitest Fake Timers for Date and Time Arithmetic in Unit Specs**: `test/vitest.setup.ts` activates fake timers for `Date` by default pinned to `1483228800000` (January 1, 2017 UTC, which falls on December 31, 2016 in US Eastern local time). Hardcoding future timestamps (e.g. `2026-10-10`) inside unit specs causes date diff arithmetic (`now - runDate`) to evaluate as negative time into the future, yielding negative millisecond spans or clock-skew fallbacks (`'just now'`). Hardcoded past timestamps in unit test fixtures must either be relative to `Date.now()` (e.g. `new Date(Date.now() - 48 * 3600 * 1000).toISOString()`) or set explicitly before December 30, 2016 (e.g. `2015-01-01`). Additionally, when testing components whose `useEffect` populates state asynchronously via `.then(...)` (such as `EditGigDialog` resolving `listVenues`), never rely on `await waitFor(() => expect(spy).toHaveBeenCalled())` followed by synchronous `screen.getByRole(...)`: the spy is invoked synchronously when `useEffect` starts, so `waitFor` can resolve before the `.then(...)` state update commits to the DOM (especially after shared fixtures call `vi.useRealTimers()`). Always use `await screen.findByRole(...)` (or assert the rendered DOM element inside `waitFor`) for elements rendered after async effect resolution.


- **AuthProvider Token Decoding in Playwright E2E Tests**: When seeding localStorage `auth` in Playwright E2E tests (`context.addInitScript`), `AuthProvider` inspects the stored token using `getTokenSub()`. If the token is not a valid base64-encoded JWT with an unexpired payload, decoding throws and resets auth state to unauthenticated (`defaultAuth`). E2E test fixtures must use a structured JWT containing a subject (e.g. `sub: 'user-123'`) and future expiration (`exp: 9999999999`), and must mock the corresponding profile retrieval endpoint (`/user/user-123`). In addition, when mocking `/user/user-*` for profile re-validation, always supply CORS headers (`access-control-allow-origin: *`, `access-control-allow-headers: *`, `access-control-allow-methods: *`) so cross-origin preflight `OPTIONS` requests from `customFetch` (triggered by the `Authorization: Bearer ...` header) do not throw CORS errors that trigger `AuthProvider`'s catch-block and unexpectedly reset the user to `defaultAuth`. Also mock background endpoints (e.g. `**/facebook/**`) to keep tests deterministic and prevent unmocked external scripts from triggering unintended UI fallbacks. Finally, wait for persistent structural milestones (such as `.menu-item` or `#mobilemenutoggle`) rather than content-dependent styling classes (like `.elevation3`, which only render when specific banner or card content is active).


- **Mocked MUI TextField in Unit Tests vs Browser DOM**: In `__mocks__/@mui/material.tsx`, `TextField` renders directly as an `<input>` element with applied props rather than an MUI wrapper `<div>` containing an inner input. Querying `screen.getByTestId('...').querySelector('input')` returns `null` in unit tests. When querying inputs in unit tests, handle both structures: `const el = screen.getByTestId('...'); const input = el.tagName === 'INPUT' ? el : el.querySelector('input')!;` so the lookup works seamlessly in both unit tests and real browser DOM trees.


- **Fixture Type Checking over Raw `as any` in Unit Tests**: Avoid casting partial or ad-hoc objects `as any` in unit tests to test utility function fallbacks (such as date extractors or formatters). Reuse a fully typed fixture and override specific properties (e.g. `{ ...baseRunFixture, startTime: '...' }`) to preserve fixture type safety and adhere to the repository's strict no-raw-any rule. In E2E and component specs, define explicit payload interfaces (such as `IinquiryPayload`) or use `Record<string, unknown>` for intercepted request bodies and typed mock events (`as unknown as React.MouseEvent<HTMLButtonElement>`) rather than `any`. When mocking `customFetch` or fetch responses in test suites, instantiate native Web API `new Response(JSON.stringify(payload), { status: ... })` fixtures instead of `{ ok, json: ... } as any`, and type component mock props using their exported prop interfaces (such as `AnnounceGigDialogProps`). When updating TypeScript interfaces to make fields optional (e.g. `Isong.url?`, `Isong.year?`), update test fixtures directly to conform to the interface rather than casting with `as any`, ensuring schema refactors surface compile-time breakages.
