# admin-outreach rules



- **Queue Header Badges vs Widened Collections & Strict Mock Typing**: When widening an in-memory collection (e.g. merging sent pitches into outreach records for the Awaiting Reply panel), ensure dedicated queue badges (such as REPLY REVIEW QUEUE) maintain their own state tracking distinct queue items rather than reading the widened set. In unit test mocks, never use raw 'as any'; use strict casts ('as unknown as typeof ...') and explicit interfaces ('IpendingReply'). Additionally, ensure downstream filter side effects (such as venues with sent records being excluded from neverPitchedVenues) are explicitly protected by unit tests.


- **Status Indicator Alignment Across Multi-State Operation Results**: In result panels, operation summaries, or progress indicators reflecting asynchronous multi-state operations (such as batch dispatch or migrations that can be in progress, successfully completed, or stopped/partially failed due to server refusal/error), status icons and semantic theme colors (e.g., success, info, warning, error) must dynamically reflect the active state. Never leave a fixed success icon (e.g. `<CheckCircle />`) or success color (`success.main`) on panels displaying stopped, paused, or partially failed states, which misleads users into reading a refusal or partial stop as a success. Ensure stopped or refused states use warning/error indicators (`<Warning />`, `warning.main`), active states use progress indicators (`<CircularProgress />`), and completed states use success indicators.


- **Review Lifetime Invalidation for Async Modal & Preview Updates**: When an asynchronous operation (such as re-generating or updating an email preview via `getPreview`) is triggered inside a modal dialog (such as `OutreachDialog`) or review flow:
  1. **Capture Review Generation**: Both the parent coordinator (`AdminOutreach`) and the modal dialog must capture the active review generation (`reviewVersion.current`) before initiating the request.
  2. **Invalidate Across Dialog Close & Session Changes**: If the user closes the dialog or switches review sessions (which increments `reviewVersion` and clears drafts), any subsequent resolution or rejection of in-flight promises must be ignored.
  3. **No Phantom State Updates**: Stale resolutions must never update parent preview collections (`setPreviews`), dialog customization state (`setRebuilt`), error state (`setUpdateErrors`), or loading spinners (`setUpdatingVenueId`). Allowing stale responses to commit after close/reopen causes phantom `Edited` marks, corrupts new review previews with old dates, and creates fingerprint mismatches that fail batch dispatch.
  4. **Deferred Request Regression Coverage**: Test suites must include regression tests that initiate an update, close and reopen the review session while the request is in flight, resolve the deferred promise, and verify that stale drafts, previews, and customizations are cleanly discarded.
  5. **Reset Entity-Linked State on Preview Open or Entity Switch**: In dialogs or preview modals that asynchronously fetch secondary metadata for an entity (such as looking up venue website and Instagram handle via `fetchVenue(gig.venueId)` in `AnnounceGigDialog`), reset dependent form and tag fields immediately at the start of the open/change effect (`setVenueTag('')`). Leaving previous values active while an async lookup is in flight risks stale handles being submitted or permanently retained if the lookup fails or returns `null`. Confirm actions must never submit stale entity attributes.
  6. **Preserve User Edits Against Late Async Completions**: When secondary async lookups populate editable fields (such as caption or tag fields), track user modifications (e.g., via `useRef` flags set on editor or input changes). When the background fetch resolves, late defaults must never overwrite or discard administrator edits or intentional field clearings made while the fetch was in flight. Test suites must include regressions asserting that delayed async completions do not clobber user-edited values and that subsequent submissions preserve the administrator's chosen payload.
